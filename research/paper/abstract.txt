Large language models (LLMs) can write unit tests for untested legacy code, but practical generators keep only tests that pass, and recent studies show that this filter locks existing bugs into the generated suite. We present Code2Test, an open-source tool for Python that first infers, stores and lets developers edit an explicit statement of intent for every function and class. It generates pytest tests against that intent, executes them, repairs failures from their pytest output, and diagnoses tests that still fail as a wrong test, a code bug or a wrong intent. Suspected code bugs are kept as expected failures with the diagnosis attached, so the written suite always passes while the signal survives. A built-in benchmark reports mutation score and the accuracy of the diagnosis on failures of known cause. On two open-source libraries (426 and 2,170 lines) with two MiniMax models, Code2Test produced passing tests for 96-100% of components. Before any repair, 85-99% of generated tests passed, and the suites killed 59-78% of sampled mutants. The diagnosis was correct on 97-100% of failures of known cause. Surviving mutants concentrated in one function that a run tested only structurally and in string literals that tests do not observe, and nearly all intents came from docstrings. Because both libraries are mature, the study measures validity and fault detection, not whether intent-first generation avoids locking in bugs; we describe the experiment that would. We also report eight failure modes that appeared only with a real model. Each of the tool's techniques has a precedent; its contribution is their combination in one open tool and the empirical lessons from running it.
